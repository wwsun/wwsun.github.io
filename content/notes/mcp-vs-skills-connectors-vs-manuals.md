> [!note] 核心结论
> **MCP 的本质是连接器（Connectors）**，定义标准通信协议，解决“如何安全跨平台接入外部实体（What）”；**Skills 的本质是说明书（Manuals）**，封装领域心智模型，解决“如何高效规避暗坑使用系统（How）”。企图用「本地 CLI + Skill」取代 MCP 会导致生态碎片化与安全倒退；工业级的最佳实践是**以 MCP 奠定免安装、跨平台的安全连接底座，并在其上叠加一层轻量 Skill 作为领域备忘单（Cheat Sheet）**。可与 [[anatomy-of-coding-agent-harness]] 关联阅读。

## 核心要点与机制

### 1. 架构对比：MCP 连接器 vs. 技能说明书

| 评估维度           | Remote MCP（远程标准连接器）                                 | Capability Skills + 本地 CLI                                          |
| :----------------- | :----------------------------------------------------------- | :-------------------------------------------------------------------- |
| **跨平台可移植性** | **全平台通用**。网页端、手机端与轻量沙盒填入 URL 即用。      | **仅限重型本地终端**。无 Shell 与计算环境的手机/Web 端直接死锁。      |
| **部署与依赖维护** | **零本地依赖（Zero-Install）**。客户端无需安装任何 runtime。 | **碎片化安装**。强依赖用户手动配置 `npm`、`uv` 或 `brew` 环境。       |
| **版本无缝迭代**   | **服务端热更新**。修复 Bug 或扩展工具全球客户端瞬间生效。    | **版本滞后**。需手动更新本地 CLI 二进制与本地 Markdown。              |
| **密钥安全性**     | **标准 OAuth**。Token 存储于隔离沙盒，不向模型明文暴露。     | **明文裸奔**。通常强依赖本地 `.env` 纯文本，临时容器重启即丢。        |
| **沙盒与提权风险** | **函数级安全隔离**。仅暴露声明好的 Tool API。                | **过度提权**。模型为了运行 CLI，获得了执行任意 Shell 命令的高危权限。 |

### 2. 为什么“万物皆 CLI + Skill”是一场倒退？

- **终端沙文主义的偏见**：默认所有用户都在全功能终端中运行 Agent，切断了数以千万计在移动端、Web 端消费智能体的可能性。
- **密钥管理灾难**：缺乏标准化握手流，用户被迫申请高特权长期 Token 并以明文塞入本地环境。
- **生态割裂**：各处散落的 Markdown 说明书一旦底层 API 调整，迅速沦为失效的伪代码。

### 3. Skills 的真正统治区

反对“能力型 Skill 替代连接器”，并不代表否定 Skills。Skills 在**纯知识传递、心智模型灌输与流程约束**场景拥有不可替代的统治力：

- **编码哲学与审查标准**：指导 Agent 编写符合团队审美的 Commit、架构分层与单测准则。
- **介质解析指南**：教导模型如何借助现成脚本解包 PDF、解析复杂 XML 拓扑。
- **私有环境约定**：如规定仓库使用特定工具链读取凭证，无需为此开发冗余的 MCP。

## 实践启示 / 协同闭环

1. **组合范式：Skill 为 MCP 注入领域经验**：MCP 提供原始接口（如 `noteplan.search()`），Skill 负责注入参数约束（如强制 `YYYY-MM-DD` 格式、分页限制 `limit=50`），在模型发起调用前垫平隐蔽暗坑。
2. **让 Agent 自动为 MCP 沉淀 Skill**：在会话中调试通一个复杂 MCP 后，让 Agent 将调试过程中发现的注意要点与边缘格式打包写成一份针对该 MCP 的 Skill，使后续会话免于重复试错。
3. **职责划分铁律**：涉及跨系统远程通信、数据鉴权与沙盒隔离，坚决采用 MCP；涉及流程规范、代码审美与思维定式约束，坚决采用 Skill。
