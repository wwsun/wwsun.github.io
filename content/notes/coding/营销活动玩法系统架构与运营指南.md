# 营销活动玩法系统（Campaign Engine）架构与运营指南

## 一、 系统全景概览

营销活动玩法系统旨在通过模块化、事件驱动的架构，提供高复用、高扩展的营销玩法支持。系统整体按照 **“引流蓄水 $\rightarrow$ 行为做功 $\rightarrow$ 资产消耗 $\rightarrow$ 权益履约”** 四个阶段进行解耦。

```
[引流蓄水] ──> [行为做功] ──> [资产消耗] ──> [权益履约]
 Reservation      Task          Lottery       Gift
                  Vote          Exchange

```

---

## 二、 核心概念双视角对照表

| 模块名称               | 程序员视角（系统实现与抽象）                                                                                | 运营视角（业务玩法与目标）                                                                              |
| ---------------------- | ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| **预约 (Reservation)** | **定时召回与推送引擎**<br>管理用户预约状态，触发定时任务，通过短信/Push队列进行触达。                       | **活动预热与蓄水工具**<br>提前锁客、聚集初始流量，活动上线时进行人群精准召回。                          |
| **任务 (Task)**        | **事件驱动（Event-Driven）的状态机**<br>订阅 Pub/Sub 事件总线，过滤并计算用户行为指标，更新进度并派发代币。 | **用户行为引导器**<br>提升留存与活跃，引导用户完成指定动作（听歌、分享、登录等）以获取积分或次数。      |
| **投票 (Vote)**        | **基于身份鉴权的计数与排序模块**<br>处理配额校验、高并发点赞/计数、按身份/策略分配权重并排序。              | **高互动与 UGC 促活工具**<br>制造话题与社群传播，结合身份权益（如 VIP 多票）刺激转化。                  |
| **抽奖 (Lottery)**     | **基于概率与库存控制的算法引擎**<br>处理随机数生成、概率区间匹配、Redis 分布式锁库存扣减与预警。            | **高吸引力的低成本消耗出口**<br>用高价值大奖吸引参与，以概率机制平摊成本，消耗用户手中积攒的积分/次数。 |
| **兑换 (Exchange)**    | **确定性价格的虚拟交易商店**<br>处理确定性资产的”扣减代币 - 扣减库存 - 触发订单”的事务控制。                | **目标明确的保底消耗出口**<br>给高粘性/不愿承担抽奖风险的用户提供确定性反馈，建立长期参与预期。         |
| **礼品 (Gift)**        | **统一履约与权益解包底座**<br>屏蔽各类底层权益（VIP、优惠券、实物）发货差异，提供统一接口与重试机制。       | **奖品资产库与交付中心**<br>管理活动成本，将多种权益打包为”礼包”，实现跨玩法统一管理与发货。            |

### 2. 开发者关键关注点与技术避坑

- **Task 模块**
  - **幂等性设计**：事件总线可能发生消息重复投递，任务进度递增逻辑必须基于 `event_id` 或 `biz_unique_key` 做去重校验。
  - **解耦原则**：Task 模块只计算进度和派发资产，不关心业务动作是如何发生的。

- **Lottery / Exchange 模块**
  - **防超卖与并发控制**：库存扣减必须通过 Redis + Lua 脚本进行预扣，再异步落库。
  - **状态隔离**：抽奖逻辑只负责”判断资格 $\rightarrow$ 计算概率 $\rightarrow$ 扣减库存 $\rightarrow$ 生成中奖记录”，发货逻辑全面交由 Gift 模块处理。

- **Gift 模块**
  - **异步履约与重试**：对于第三方权益接口（如外部优惠券），发货过程必须异步化，并具备完善的失败重试队列与人工补发补偿机制。
  - **权益解包**：支持一个 `gift_id` 包含多个 `item`（如：3天VIP + 10元卷），解包逻辑对上层调用方透明。

- **Reservation 模块**
  - **成本与风控**：短信发送接口必须严格配置频控（Rate Limiting）与成本上限控制，避免被刷爆。

## 四、 运营视角：活动搭建配置 SOP

如果你需要独自配置并上线一次活动，请遵循以下标准的配置流程：

```
第一步: 资产准备    第二步: 预热设置    第三步: 规则与玩法    第四步: 消费与履约    第五步: 检查上线
[Gift 权益录入] ─> [Reservation] ─> [Task & Vote] ─> [Lottery/Exchange] ─> [试运行测试]

```

### 1. 活动搭建配置清单

#### 步骤一：底座资产配置（Gift 模块）

- 在礼品中心创建本次活动所需的权益或实物。
- 将独立权益组合成“运营礼包”（例如：将“盲盒挂件”和“满减券”打包为“满贯大礼包”）。

#### 步骤二：前置预热配置（Reservation 模块）

- 设置预约开启时间与活动正式开始时间。
- 配置预约成功后的文案及短信/Push 提醒模版。
- 设定召回触达的时间节点（如：活动开始前 15 分钟）。

#### 步骤三：用户动作与产出配置（Task & Vote 模块）

- **配置 Task**：关联目标事件（如：听歌超 1 分钟、分享活动页面），设置完成条件，以及对应的奖励（如：每次完成给 10 积分）。
- **配置 Vote**：设定投票选项、活动总票数/每日票数规则、不同身份（如 VIP 与普通用户）的票数权重。

#### 步骤四：消耗与产出配置（Lottery & Exchange 模块）

- **配置 Lottery**：将 Gift 模块配置的礼包放入 Spinach 奖池，配置对应中奖概率、总库存、每日库存上限及库存预警阈值。
- **配置 Exchange**：设定上架商品、兑换所需的积分数额、个人限购次数及总量库存。

### 2. 运营避坑指南

1. **概率与库存管理**：抽奖奖池中必须设置“保底奖品”（通常为无库存限制的虚拟小积分或安慰奖），防止大奖抽完后出现空转报错。
2. **防刷与风控**：任务与投票模块必须设置单人每日获取资产的上限，防止脚本刷号掏空奖池。
3. **成本核算**：预约短信的触达成本需提前估算；兑换商店的确定性商品必须严格盘点预算，防止高价值商品被快速兑空。

## 五、 简单速记卡片

> **预热召回靠预约 (Reservation)，互动活跃靠任务与投票 (Task & Vote)；**
> **概率确定分抽奖与兑换 (Lottery & Exchange)，发货履约全归礼品 (Gift)。**
