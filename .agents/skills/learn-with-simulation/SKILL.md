# Learn With Simulation

把一个陌生主题变成「知识库 + 可交互 3D 模拟」的学习项目。核心理念来自 [how-i-use-llms-to-learn](https://laurentiugabriel.github.io/blog/articles/how-i-use-llms-to-learn/)：**不要让 AI 直接口头解释一个主题**——那种输出太简化、容易带幻觉，也不利于记忆。真正有效的路径是：先让 AI 构建结构化知识库，再验证准确性，最后把知识变成可以动手玩的可视化模拟。

## 为什么这么做

- **直接解释 vs 构建知识库**：让 AI「解释 X」得到的是流水账式的要点列表；让 AI「为 X 构建知识库」得到的是有结构、有层次、可反复查阅的内容，中间还强迫模型把主题拆解成清晰的章节与概念。
- **验证在可视化之前**：LLM 的输出来源混杂，必须先用交叉验证把幻觉拦在知识库外面。先验证、再可视化，模拟动画才配得上「100% 准确」。
- **模拟帮助记忆**：把概念对应到可视化场景里的物体和过程，比阅读文字记忆牢固得多。低多边形风格（类似《过山车大亨》）保留了可识别性，又避免了高精度建模的工程负担。

## 工作流

### 第 1 步：规划模式构建知识库

先花时间确定主题范围与结构，再动笔写内容。流程：

1. **扫描既有笔记**：用 grep 在 `content/` 下搜主题关键词（中英文都搜），批量读取所有可关联的笔记。它们既是内容基础（避免凭记忆写、防止与既有笔记矛盾），也是 Wiki-link 的链接目标。动笔前如果发现还有相关笔记没读，先补齐再写。
2. **划定范围**：和用户确认主题边界——学多深、面向什么用途、有没有明确想覆盖/跳过的部分。范围不清就提问，不要默认「全面覆盖」。
3. **搭大纲并确认**：把主题拆成 4-8 个递进的章节，每个章节对应一个知识库笔记文件。结构要符合认知顺序（先是什么、再为什么、最后怎么做），章节之间用 Wiki-link 互链。拟定大纲后展示给用户（每章一行：文件名 + 一句话摘要），用 ask_user 确认，默认选项为「大纲没问题，开始写」。避免写完才发现结构不符预期。
4. **逐章构建**：按大纲逐章撰写 Markdown 笔记。每篇笔记统一结构：
   - 开头一句直觉引入（讲给「会学习但不懂这个领域的人」的口吻，先直觉后严谨）
   - 分节展开机制：关键概念给出定义 + 一个具体例子或类比，术语首次出现时标注英文原名
   - 「一句话总结」小节
   - 「来源」小节（先留空，第 2 步审查后回填）
   - 「相关笔记」小节：用 `[[Wiki-link]]` 链接到其他章节和相关既有笔记
   > 参照：`content/learning/chip-manufacturing/` 与 `content/learning/llm/` 两个项目均遵循此结构。
5. 产出 `index.md` 作为学习主页：主题一句话简介 + 章节列表 + 每章一句话摘要 + 「怎么玩模拟」入口说明。

### 第 2 步：准确性审查

知识库写完后，换一个视角审查它：

1. **逐章审查**：逐条核验笔记中的事实性陈述——数字、时间、名称、因果关系、术语定义。写笔记时就顺手维护一份「待验证数字清单」（精确数字、年份、参数规模等），审查时按清单逐项核验。常识级事实（如「GPT-3 有 1750 亿参数」这类广为人知的）不必全部联网验证。
2. **交叉验证**：按优先级选择来源，能修的直接修进笔记：
   1. 维基百科 REST 摘要 API（`https://en.wikipedia.org/api/rest_v1/page/summary/<条目名>`，比抓全文省大量上下文）
   2. 官方文档
   3. arXiv 论文摘要页
   4. 二手来源（博客、教程）——只作旁证，不作裁决依据

   **验证预算**：每条事实最多 2-3 次抓取尝试。失败即停止纠缠，标「待验证」，不要为了一个数字反复换来源。

3. **修正 + 记录**：修正后的笔记要保持原结构。审查记录分两层：
   - 各章文末「来源」小节：逐条列出「陈述 + 已核实/待验证 + 出处」（格式见 chip-manufacturing 与 llm 项目）
   - index.md「已核实来源」汇总清单 + 一段「置信边界」：写明哪些是官方口径、哪些是行业推断、哪些待验证

   验证不了的陈述不要默默删掉——标注为「待验证」，让用户知道知识库的置信边界。

### 第 3 步：低多边形 3D 模拟（核心步骤）

生成一个单文件 HTML 模拟页面（`simulation.html`），把知识库里的核心过程可视化：

- **技术**：用 [Three.js](https://threejs.org/)（CDN 引入），单 HTML 文件，无构建步骤、无外部依赖。场景用低多边形风格：平面着色（flat shading）、几何体用基本形状组合、颜色明快、类似《过山车大亨》的玩具感。
- **参照模板**：先读既有模拟页再动笔，直接套用其骨架（场景初始化、灯光、状态机、阶段面板、控件栏）。两个成熟参照：
  - `quartz/static/learning/chip-manufacturing/simulation.html`——「工作站式」：传送带 + 多个工作站 + 主角物体随阶段变形（另含问答关卡示例）
  - `quartz/static/learning/llm/simulation.html`——「旅程式」：单一主角依次经过多个阶段，相机跟随，CSS 投影阶段标签

  通用经验：每阶段一个 `updateStageN(t)` 函数 + 一个 STAGES 配置数组（标题、解说文字、对应笔记链接），主循环只做分发。

- **内容**：模拟要覆盖主题中最核心的一条「主线流程」——比如芯片制造的完整工序链、某个系统的数据流、某个机制的作用原理。不是静态展品，是**动起来的流程**：物体移动、形态变化、阶段递进。**阶段数 = 知识库章节数（或主线章节数）**，每个阶段的解说文字必须能对应到笔记里的具体小节。
- **配套**：场景中要有阶段标签说明当前步骤；页面下方或侧边放文字解说，与知识库笔记互链。**模拟页里的知识库链接必须用站内绝对路径**（如 `/learning/llm/tokenization`）——HTML 位于 `/static/` 下，相对路径会断。
- **UX 要求**：页面在桌面和手机上都要可用（响应式画布）；提供暂停/继续控件、阶段跳转控件；加载快（几何体数量克制）。
- **自检**：写完后提取 `<script type="module">` 内容用 `node --check` 验证语法；核对所有 `document.getElementById` 引用的 id 都存在于 HTML。环境安装了 Playwright 时，可加一步无头截图验证动画（可选）。
- **质量门槛**：模拟的每个阶段必须与知识库内容一致——模拟是知识库的可视化延伸，不是独立创作。如果知识库里没有的细节，不要在模拟里编造。

### 第 4 步：发布到知识库

- 知识库笔记放在 `content/learning/<主题英文短横线-slug>/` 目录下：
  - `index.md` — 学习主页
  - `<章节>.md` × 若干 — 知识库笔记（Quartz 会渲染为站点页面）
- 模拟页面放在 `quartz/static/learning/<slug>/simulation.html`（注意是 `quartz/static/`，不是仓库根 static/，更不是 content/——Quartz 的 Static emitter 只复制 quartz/static/，而 content 下的 HTML 会被 Assets emitter 剥离扩展名导致无法渲染）。站点 URL 为 `/static/learning/<slug>/simulation.html`，学习主页用标准 Markdown 链接（非 wikilink）指向它。
- 新建 `content/learning/index.md` 分类索引（若无），为每个主题写一句话简介；已有则追加本主题一行。
- 单文件 prettier 格式化 Markdown 文件（`npx prettier --write content/learning/<slug>/*.md`）。
- 本地验证（必做，保持轻量——不需要起服务器）：
  1. 文件位置自检：确认 `content/learning/<slug>/` 下笔记齐全、模拟页位于 `quartz/static/learning/<slug>/simulation.html`
  2. 模拟页 JS 通过 `node --check` 静态检查
  3. `npx quartz build` 一次覆盖两层验证：构建日志无断链警告（wiki-link 与静态资源路径全部有效）；`public/learning/<slug>/` 与 `public/static/learning/<slug>/simulation.html` 产物存在
- 本地验证（可选，平时跳过）：`npx quartz build --serve` + curl 抽查 HTTP 200，仅在改动涉及站点结构（如 quartz 配置）、或怀疑模拟页内链有问题时做。build 成功 + public/ 产物存在时，HTTP 层基本必然可访问；301 到无扩展名 URL 是 Quartz 固有行为（curl 时用 `-L` 跟随即可），无需每次复验。
- 提醒：新文件在 git commit 之前，Quartz 构建会警告「dates will be inaccurate」（用文件 mtime 推断日期）。提交后日期自然准确；若需立即可靠的日期，在 frontmatter 显式写 `date`。
- 完成后给用户一句话总结：知识库覆盖了什么、模拟展示了什么、哪些内容标了「待验证」。

## 迭代改进（可选）

用户玩过模拟后，可以按需继续：

- **加挑战**：在模拟里加入问答关卡——回答上一阶段的问题才能进入下一阶段，巩固记忆。
- **提精度**：低多边形不够直观时，把关键物体替换为更精确的模型。
- **扩场景**：为主流程之外的旁支机制增加第二、第三个模拟场景。

## 质量检查

发布前逐项核对：

- [ ] 知识库每篇笔记都有 frontmatter（title、tags、description）
- [ ] 每篇笔记结构完整：直觉引入 + 机制/定义 + 例子 + 一句话总结 + 来源 + 相关笔记
- [ ] 章节间 Wiki-link 互链完整，学习主页链接全部有效，且已链接到 content/ 下所有相关既有笔记
- [ ] 审查记录存在：各章「来源」小节逐条标注已核实/待验证，index.md「已核实来源」清单非空且含置信边界
- [ ] 模拟页面单文件、CDN 引入 Three.js、响应式、有暂停控件
- [ ] 模拟页面位于 `quartz/static/learning/<slug>/simulation.html`，构建后存在于 `public/static/` 对应路径
- [ ] 模拟每个阶段都能在知识库中找到对应内容（阶段数 = 章节数，解说文字与笔记小节一一对应）
- [ ] 模拟页内知识库链接为站内绝对路径
- [ ] 模拟页 JS 通过 `node --check` 静态检查
- [ ] `content/learning/index.md` 已更新
