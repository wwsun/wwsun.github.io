# Post Clipping

把一篇网页文章加工成归档到 `content/clippings/` 的双语对照笔记。流程固定：抓取 → 翻译 → 术语表 → 归档。本 skill 同时涵盖原 clipping-post-optimizer 的产出质量规则，一步到位，产出即为终稿。

## 为什么是双语对照

这个知识库的 clippings 采用「英文原段 + 中文译段」交替的格式。保留原文不是为了省事：读者（包括未来的你）需要能核对译文、对照术语，Quartz 站点的访客也可能两种语言都想看。所以原文一段都不能丢、不能合并、不能重排。译文也不是机翻贴图，要让中文读者顺畅读完。

输出格式由用户决定：全文逐段对照是 `content/clippings/` 里数百篇既有笔记的固定格式，也是本任务的既定要求。保持这个格式，产出的笔记才能与目录中其他剪报无缝衔接。

## 工作流

### 1. 抓取正文

- 优先用 defuddle 提取正文（`defuddle <url>`），它能剥掉导航、广告等杂物；不可用时改用 web_fetch。
- 记录三项元数据：原文 URL、作者、发布日期。从页面元数据或正文中提取，拿不到就省略对应字段——不要编造。
- 抓取失败或撞上付费墙时，停下来如实告诉用户，不要凭印象续写正文。

### 2. 查术语参考表

先读 `references/glossary.md`。表里已有译法的术语直接沿用——**译法一旦收录就固定下来**，这是术语一致性的来源：同一篇里的 "guardrails" 和半年前那篇里的 "guardrails" 必须是同一个中文词。这是机械步骤，不要凭记忆翻译。

### 3. 翻译

按下方「翻译原则」逐段翻译。翻译全文，一段不落——文章再长也要完整产出，不能只翻前半篇。

### 4. 构建术语表

按「术语表」一节抽取 5-20 个术语，生成文章内的术语表。

### 5. 归档

按「输出格式」创建笔记，更新 `content/clippings/index.md`，把新术语追加进 `references/glossary.md`，最后单文件 prettier 格式化。

## 翻译原则

1. **技术术语保留英文**。API 名称、类名、函数名、参数名、文件路径、命令保持英文原文。它们不译不是因为难，而是译了之后读者反而对不上官方文档——`useState`、`~/.config`、`apt install` 永远不译。
2. **术语一致**。同一术语全文统一译法；术语表定译之后，正文不得出现第二种译法。第 2 步查参考表就是为了保证跨文章也一致。
3. **代码块原样保留**。代码、命令、配置文件只翻译其中的注释，其余一字不动——缩进、空行、标点都不能变。译文段落紧跟在对应代码块后面。
4. **拆长句**。英文的从句套从句直译成中文会变成一堵墙。按意群拆成中文短句，可以断句、调整语序，译文比原文多几句完全没问题。
5. **补充语境**。原文隐含的前置知识（缩写全称、只在一定语境下成立的背景）用括号或「译者注：」补出。宁多一句解释，不留一处黑话。
6. **URL 全保留**。原文里的每个链接都要以 Markdown 链接形式出现在译文对应词上，地址一字不改。链接比正文难复制，丢了读者就回不去了——整篇产出应保留原文绝大部分链接（而不是只剩原文标题那一个），链接少的文章尽量一个不落。
7. **段落对齐**。英文原段和中文译段交替排列，中间用空行分隔，不加任何前缀标记（不写「EN:」「译:」之类）——交替顺序本身就是标记。中英段落必须一一对应，不合并、不遗漏、不重排。

## 术语表

文章头部生成术语表，规则：

- 只收对理解文章有实质帮助的术语：专有技术名词、框架名、协议名、缩写。
- 每行三个字段：英文原文、中文译法、一句话说明。
- 保留英文的术语（无通行中文译法的专有名词），译法列直接写英文原文，说明列写它的实质含义——不要写「保留英文」这类元注释，说明列只说这个术语是什么、干什么用的。
- 数量控制在 5-20 个。少于 5 个说明可能漏了；多于 20 个说明在凑数。
- `references/glossary.md` 已有译法的直接使用；没有的根据上下文定译。
- 新定译的术语，归档时追加到 `references/glossary.md`，保持表格按英文首字母排序。

## 输出格式

文件名用英文标题的 URL 友好 slug（如 `the-law-of-leaky-abstractions.md`）。内容按 `content/clippings/` 现有笔记的格式：

```markdown
---
title: 中文标题
description: 一句话中文描述，说清文章讲了什么
tags:
  - clippings
  - <1-3 个主题标签，英文小写短横线>
source: <原文 URL>
created: YYYY-MM-DD
author: <作者>
---

## 中文标题

> **原文**：[<英文标题>](URL) | 作者：<作者> | 日期：<发布日期>

## 📝 摘要

<3-5 句话概括文章核心内容，纯中文>

## 📋 术语表

| 英文   | 中文   | 说明         |
| ------ | ------ | ------------ |
| <术语> | <译法> | <一句话说明> |

---

## 正文（双语对照）

<英文原段>

<中文译段>

<英文原段>

<中文译段>
```

`📝 摘要` 与 `📋 术语表` 是 clippings 目录的既有标记，沿用它们保持目录内风格统一。`author` 字段为纯文本作者名（不用 wikilink 或 YAML 列表）。标题处理：`##` 及以下标题若中英文并列，只保留中文；没有通行中文译法的专有名词保留英文。原文的一级标题（`#`）不出现在正文里，用 `## 中文标题` 开头。

## 质量检查

归档前通读一遍，逐项核对：

- **脚注对齐**：中文段的 `[^n]` 引用与英文原段一一对应，编号和数量一致；修掉自动翻译常见的 `\[ 13\]`、`[^35, 2, 5]` 之类错误。
- **超链接同步**：英文段的每个 `[文本](URL)` 在中文段对应词上有完全相同的链接。
- **段落对齐**：中英段落逐段成对，无遗漏、无合并。
- **术语一致**：对照术语表通读，正文里没有第二种译法。

## 备选格式：双语精读

全文逐段对照是首选。只有当确实无法按全文逐段对照执行时，才改用双语精读格式——不要自行发明别的格式：

- frontmatter、摘要、术语表、链接保留、术语表追加、index.md 更新等要求全部不变。
- 正文按原文结构逐节组织：每节先给 1-3 句核心英文引语，再给覆盖该节全部论点的中文详细解读；全文论点一个不落。
- 正文标题处标注为 `## 正文（双语精读）`，开头加一行说明改用精读格式的原因。
- 完成前同样执行「质量检查」中适用的项目。

## 归档动作

1. 在 `content/clippings/` 创建 `<slug>.md`。
2. 在 `content/clippings/index.md` 追加一行：`- [[<slug>|<中文标题>]] — <一句话简介>`，保持与现有条目相同的格式。
3. 本次定译的新术语追加到 `references/glossary.md`（已收录的跳过）。
4. 单文件格式化：`npx prettier --write content/clippings/<slug>.md`。
