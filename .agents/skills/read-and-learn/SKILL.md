# Read and Learn：资料精读与学习入库工作流 (Notes & Clippings)

本 skill 是外部资料进入 Obsidian/Quartz 知识库的统一入口，支持**任意输入源**（网页 URL、本地文件、粘贴文本）与**两种产出模式**：

- **模式 A：精炼学习笔记（`content/notes/`）** —— 控制在 **3–5 分钟阅读时长（800–1,500 字）**，砍掉背景寒暄与冗余铺垫，直击核心结论、关键机制与可落地的实践要点，并关联知识库既有 `[[Wiki-link]]`（适合快速消化技术方案、工具规范与工程方法论）。
- **模式 B：全文双语对照剪藏（`content/clippings/`）** —— 按需检索术语表、生成 5-20 条核心术语表、全文逐段「英文原段 + 中文译段」交替对齐，可选费曼式英语复盘（适合深度长文、外刊博客原汁原味归档与英语精读）。

---

## Step 1：获取资料与意图消歧（必做）

### 1.1 读取资料内容

根据用户提供的资料类型获取全文：

- **本地文件**（如 `@[/path/to/file]`）：直接用文件读取工具读取完整内容。
- **网页 URL**：优先用 `defuddle <url>` 提取正文（剥离导航与广告）；不可用时改用网页抓取工具。记录原文 URL、作者、发布日期（拿不到则省略，不编造）。若抓取失败或遇付费墙，立即停下如实告知用户，绝不凭印象编造正文。
- **直接粘贴的文本**：直接使用上下文中的文本。

### 1.2 判断或询问归档模式

在动笔撰写前，先判断用户是否已明确归档模式：

1. **意图明确 → 直接执行对应模式**：
   - 明确要求 **模式 A（学习笔记 / `notes`）**：用户提到「沉淀到 notes」「写篇学习笔记」「拆解整理进 notes」「提炼核心要点存知识库」等。
   - 明确要求 **模式 B（全文翻译 / `clippings`）**：用户提到「全文翻译」「剪藏」「存到 clippings」「双语对照」「逐段翻译」等。
2. **意图模糊 → 必须向用户提问确认**：
   - 当用户仅说「帮我整理一下这份文档」「把这个存进知识库」「帮我学习并归档这篇资料」等，无法100%确定是想要「提炼学习笔记（`notes`）」还是「全文双语翻译（`clippings`）」时，**必须调用提问工具（如 `ask_question`）让用户选择**。
   - 提问时，结合刚读取的资料特征给出推荐项（例如：若是系统提示词、配置清单、多章节教程，推荐整理为 `notes` 学习笔记；若是观点鲜明的英文长文博客，推荐译为 `clippings` 双语剪藏）：
     - 选项 1：`提炼为精炼学习笔记（归档至 content/notes/，3-5 分钟阅读要点，含核心结论与关键机制）`
     - 选项 2：`全文中英双语对照翻译（归档至 content/clippings/，含术语表与逐段双语对齐）`

## 模式 A：整理精炼学习笔记（`content/notes/`）

模式 A 的目标是产出一篇**「3–5 分钟即可读完的高信噪比要点笔记」**（全文严格控制在 **800–1,500 字 / 60–120 行 Markdown** 以内）。若读者需要逐字研读全文，应使用模式 B（`clippings`）；模式 A 只留干货与可复用洞见。

### A.1 检索关联笔记与标签

1. 搜索 `content/notes/` 及其他子目录下主题相近的已有笔记，准备用最短路径 `[[Wiki-link]]`（如 `[[claude-code]]`）建立双向连接（控制在 1–4 个强相关链接）。
2. 参考 `content/tags.json` 中已有的标签体系，挑选 2-4 个准确的 `kebab-case` 标签（如 `agent`、`prompt`、`workflow`）。

### A.2 精简原则（四删四留）

- **删背景寒暄，留开门见山**：禁止写「随着 AI 的飞速发展……」等行业套话；首段直接进 `> [!note] 核心结论`。
- **删次要叙事，留机制与数据**：砍掉原文中的铺垫故事、修辞比喻与边缘案例，只保留核心因果机制、权衡取舍（Trade-offs）与关键量化指标。
- **删大段摘抄，留极简示例**：禁止大段粘贴原文或逐段附「原文 + 译文解析」；仅在确有必要时内联不超过 15 行的最小可用代码/配置片段。
- **删装饰图表，留高密度结构**：普通列表或单张对比表能说清的逻辑，绝不强行画 Mermaid 图；仅当涉及多阶段流转或架构拓扑时才画一张精简图。

### A.3 笔记结构与撰写规范

文件名使用英文描述性短横线格式：`content/notes/<slug>.md`。采用紧凑的三段式骨架：

```markdown
---
title: <清晰紧凑的中文标题>
tags:
  - <tag-1>
  - <tag-2>
description: <一句话概括笔记核心内容与价值>
source: <可选，外部 URL；本地无 URL 文件可省略或填来源说明>
---

> [!note] 核心结论
> <用 2-3 句话直接给出资料的核心定位、关键结论与解决的核心问题，并顺手用 [[Wiki-link]] 关联 1-3 篇知识库已有相关笔记。>

## 核心要点与机制

<提炼 3-5 个核心要点。优先使用一张对比表格或紧凑的二级列表拆解关键机制、设计权衡或量化规律。若确有复杂状态流转/架构层次，可辅以一张精简 Mermaid 图（节点文本含括号等特殊字符时用双引号包裹，如 id["标签 (说明)"]）。>

## 实践启示 / 速查清单（可选）

<提炼 3-5 条可直接落地的行动指南、配置速查或避坑法则（Actionable Takeaways）。若前文已涵盖则省略本节。>
```

**模式 A 写作约束（严格遵循仓库 `AGENTS.md`）**：

- 使用简体中文（`zh-CN`），保持表达紧凑、客观、清晰，全文篇幅控制在 **800–1,500 字**。
- **禁止在标题或正文中使用 emoji**。
- 善用 Obsidian Callout（`> [!note]`、`> [!tip]`、`> [!warning]`、`> [!important]`）突出重点，但全文 Callout 不超过 2 个。
- 内部链接统一使用最短路径 `[[Wiki-link]]` 格式。

### A.4 归档与收尾动作

1. 将文件写入 `content/notes/<slug>.md`。
2. 运行单文件格式化：`npx prettier --write content/notes/<slug>.md`。
3. 同步全站标签索引：`npm run sync-tags`。

## 模式 B：全文双语对照剪藏（`content/clippings/`）

这个知识库的 `clippings` 采用「英文原段 + 中文译段」交替的格式。保留原文是为了让读者能随时核对译文、对照术语；所以原文一段都不能丢、不能合并、不能重排，译文也要拆解长句、自然流畅。

### B.1 按需检索术语参考表与关联笔记

1. **按需查术语表（禁止全量读取）**：先从待译文章中识别 5–20 个核心候选术语，使用搜索工具（如 `grep`）在 `.agents/skills/read-and-learn/references/glossary.md` 中检索这些候选词。表里已有译法的术语直接沿用——**译法一旦收录就固定下来**，保证跨文章术语一致。
2. **检索关联笔记**：搜索 `content/` 下与本文核心主题直接相关的已有笔记，准备在「摘要」或「术语表说明列」中使用最短路径 `[[Wiki-link]]` 关联（**双语对照正文中不插入内部链接**，以保持原文与译文的纯净对应）。

### B.2 翻译原则

1. **技术术语保留英文**。API 名称、类名、函数名、参数名、文件路径、命令保持英文原文（如 `useState`、`~/.config`、`apt install` 永远不译）。
2. **术语一致**。同一术语全文统一译法；术语表定译之后，正文不得出现第二种译法。
3. **代码块原样保留**。代码、命令、配置文件只翻译其中的注释，其余一字不动——缩进、空行、标点都不能变。译文段落紧跟在对应代码块后面。
4. **拆长句**。英文的从句套从句直译成中文会变成一堵墙。按意群拆成中文短句，可以断句、调整语序，译文比原文多几句完全没问题。
5. **补充语境**。原文隐含的前置知识（缩写全称、特定背景）用括号或「译者注：」补出。
6. **URL 全保留**。原文里的每个链接都要以 Markdown 链接形式出现在译文对应词上，地址一字不改。
7. **段落对齐**。英文原段和中文译段交替排列，中间用空行分隔，**不加任何前缀标记**（不写「EN:」「译:」之类）——交替顺序本身就是标记。中英段落必须一一对应，不合并、不遗漏、不重排。

### B.3 构建术语表

文章头部生成术语表，规则：

- 只收对理解文章有实质帮助的术语：专有技术名词、框架名、协议名、缩写。
- 每行三个字段：英文原文、中文译法、一句话说明（若对应本知识库已有笔记，可在说明列中用 `[[Wiki-link]]` 关联）。
- 保留英文的术语（无通行中文译法的专有名词），译法列直接写英文原文，说明列写它的实质含义——不要写「保留英文」这类元注释。
- 数量控制在 **5-20 个**。
- `references/glossary.md` 已有译法的直接使用；没有的根据上下文定译，并在归档时按英文首字母排序局部追加到 `references/glossary.md`。

### B.4 输出格式

文件名用英文标题的 URL 友好 slug：`content/clippings/<slug>.md`。格式如下：

```markdown
---
title: 中文标题
description: 一句话中文描述，说清文章讲了什么
tags:
  - clippings
  - <1-3 个主题标签，英文小写短横线>
source: <原文 URL，若为本地无 URL 资料可省略>
created: YYYY-MM-DD
author: <作者，纯文本，若未知可省略>
---

## 中文标题

> **原文**：[<英文标题>](URL) | 作者：<作者> | 日期：<发布日期>

## 📝 摘要

<3-5 句话概括文章核心内容，纯中文；若涉及知识库已有专题笔记，可在此处自然织入 1-3 个 [[Wiki-link]]>

## 📋 术语表

| 英文   | 中文   | 说明         |
| ------ | ------ | ------------ |
| <术语> | <译法> | <一句话说明> |

---

## 正文（双语对照）

<英文原段>

<中文译段>

<英文原段>

<中文译段>
```

> 注：`📝 摘要` 与 `📋 术语表` 是 `clippings` 目录数百篇既有剪报的传统固定章节标记，在模式 B 中予以保留以维持目录内风格统一。标题处理：`##` 及以下标题若中英文并列，只保留中文；无通行译法的专有名词保留英文。原文的一级标题（`#`）不出现在正文里，用 `## 中文标题` 开头。

### B.5 备选格式：双语精读

全文逐段对照是首选。只有当确实无法按全文逐段对照执行时，才改用双语精读格式：

- frontmatter、摘要、术语表、链接保留、术语表追加等要求全部不变。
- 正文按原文结构逐节组织：每节先给 1-3 句核心英文引语，再给覆盖该节全部论点的中文详细解读；全文论点一个不落。
- 正文标题处标注为 `## 正文（双语精读）`，开头加一行说明改用精读格式的原因。

### B.6 质量检查与归档动作

归档前逐项核对：

- **脚注对齐**：中文段的 `[^n]` 引用与英文原段一一对应，修掉 `\[ 13\]` 之类格式错误。
- **超链接同步**：英文段的每个 `[文本](URL)` 在中文段对应词上有完全相同的链接。
- **段落对齐**：中英段落逐段成对，无遗漏、无合并。
- **术语一致**：对照术语表通读，正文里没有第二种译法。

执行归档：

1. 在 `content/clippings/` 创建 `<slug>.md`。**超长文防截断机制**：若原文较长（如超过 2,500 词）导致单次输出可能触及长度上限，先调用 `write_file` 写入头部与前半部分章节，再使用 `write_file`（`Append=true`）按章节分批追加剩余双语段落，严禁删减、合并段落或中途截断。
2. 将本次新定译的术语按英文首字母顺序局部追加到 `.agents/skills/read-and-learn/references/glossary.md`（先定位对应首字母所在行区间再编辑，已收录的跳过）。
3. 单文件格式化：`npx prettier --write content/clippings/<slug>.md`。
4. 同步全站标签：`npm run sync-tags`。

### B.7 英语学习复盘（费曼学习法，可选）

模式 B 归档完成后（或用户在模式 A 后主动要求练英语时），主动询问用户是否进入英语学习复盘（推荐选项为「开始复盘」，用户跳过则直接收尾）。

#### 引导方式

- 复盘全程对话式：一次只引导一个小任务，用户先输出，Agent 后反馈。参考答案要憋到用户卡壳之后才给。
- 轻量、不考试：一轮练习 2-4 个短语或要点，总量控制在十分钟左右；用户想跳过某一步就跳过。
- 反馈必须有依据：每条指向原文对应段落（直接引用原句），不说空泛的「表达不够好」。
- 用户的英语输出不要求语法完整：短语、单词、中英混合都算数，重点是把意思说出来。

#### 三步引导

1. **关键短语热身（Key phrases）**：从文章里挑 5-8 个值得学的英文短语（地道表达 + 2-3 个核心术语）。分 2-3 轮练习，每轮 2-4 个，两种玩法交替：
   - **认读**：Agent 给英文短语（不带含义），用户说意思；
   - **回忆**：Agent 给中文含义，用户回忆对应的英文短语。
   - 用户卡壳时先给上下文提示（短语出现的原句），再不行才给答案。
2. **要点回顾（Key points）**：请用户用短语式英语或中英混合，以 bullet 形式列出文章的关键要点（3-6 条）。列出后 Agent 对照原文指出遗漏的要点和说法问题（1-3 条，附原文依据），最后补全漏掉的要点。
3. **复盘落盘（可选）**：结束后询问用户是否把复盘要点追加到笔记末尾。同意才追加，随后重新执行 `npx prettier --write`；拒绝则不写。

#### 复盘落盘格式

追加到笔记末尾，与正文之间用 `---` 分隔：

```markdown
---

## 📖 学习复盘

> 记录于 YYYY-MM-DD。费曼式复盘：关键短语 + 要点回顾。

### 关键短语

- <短语> —— <含义或用法>

### 要点回顾

- <用户回顾的要点，保留原样>
```
